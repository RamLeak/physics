# Фаза 0.2 — Парсинг PDF в billets.json

## Контекст

В корне проекта (`C:\Projects\physics`) лежит файл `Билеты_по_физике_10г_полный.pdf`. Его нужно распарсить в `src/data/billets.json` и извлечь схемы задач в `public/images/`.

PDF содержит **20 билетов**. У каждого билета: 2 теоретических вопроса + 1 задача (с условием, "Дано", решением и ответом). У задач 1, 2, 3, 4, 5, 6, 7, 8, 10, 15, 17, 19 есть схемы/рисунки, встроенные в PDF.

## Что делать пошагово

### ШАГ 1. Извлечение картинок задач

Используй Python библиотеку `PyMuPDF` (fitz) или `pdfimages` (если установлен poppler), чтобы извлечь встроенные растровые изображения из PDF.

**Что важно:** в PDF встроены превью-изображения для схем задач. Они должны попасть в `public/images/` как `billet-1-problem.png`, `billet-2-problem.png` и т.д.

Картинки есть для задач: **1, 2, 3, 4, 5, 6, 7, 8, 10, 15, 17, 19**. Остальные задачи без схем — не паникуй, если изображений извлечётся меньше 20. Сопоставь извлечённые изображения с правильными билетами вручную в коде (по странице PDF, где они находятся).

Если автоматически сопоставить не получается — напиши скрипт, который складывает все картинки в `public/images/raw/` с именами `page-N-img-M.png`, и в финальном отчёте укажи, что я должен сам разложить их по билетам.

### ШАГ 2. Парсинг текста и создание `src/data/billets.json`

Структура файла — точно по схеме ниже. Пример полностью раскрытого билета 1 даётся как эталон качества — придерживайся такой же атомарной разбивки для всех 20.

### ШАГ 3. Простановка дубликатов

В каждом билете есть поле `theory_duplicates` (массив объектов). Список дубликатов даётся ниже.

### ШАГ 4. Создание `connected_recall.checklist` для каждого билета

Это список из 5-10 коротких пунктов, которые должны прозвучать при устном пересказе билета. Это не подсказки, а **проверочный список после рассказа**: рассказал — глянул чек-лист — увидел, что упустил.

## Атомарная разбивка — правила

1. **Одна карточка = один атом знания**, который можно проверить одним вопросом ("что такое СО?", "запиши закон Ома").
2. **3-6 карточек на теор.вопрос**. Если получается 1-2 — слишком крупно. Если 8+ — слишком мелко.
3. **Формулы попадают в карточки целиком** (не разноси одну формулу с её расшифровкой по разным карточкам).
4. **`key_terms`** — это массив терминов, которые должны быть в ответе ученика. Используется потом для проверки свободного ответа.
5. **`content`** может содержать markdown: `**жирный**`, списки, переносы строк `\n`. Формулы — обычным текстом (не LaTeX).

## Что делать с задачами

Каждая задача в PDF имеет блок "Дано" и блок "Решение". Парси так:

- **`condition`** — текст условия (то, что в курсиве в PDF, до блока "Дано").
- **`given`** — массив строк из блока "Дано". Если в PDF указано "СИ" с переводом — объединяй: `"m = 100 г = 0,1 кг"`.
- **`find`** — что найти (из строки "Найти:").
- **`solution_steps`** — массив из 2-4 шагов, **по сути решения, не дословно**. Это потом будет использоваться для режима "слепое решение задач" — ученик впишет свой ход, мы сверим.
- **`answer`** — финальный численный ответ с единицами.
- **`image`** — путь вида `/images/billet-N-problem.png`. Если для этой задачи картинки нет — поставь `null`.

---

## Что делать с `connected_recall.checklist`

Для каждого билета составь чек-лист устного пересказа: **5-10 пунктов**, охватывающих оба теор.вопроса (примерно по 4-5 на каждый).

Каждый пункт — это **то, что должно прозвучать**, в формате глагола: "упомянуть", "назвать", "записать формулу", "объяснить разницу", "привести пример".

Не делай чек-лист простым повторением `topic` карточек — он должен фокусироваться на ключевых смыслах, без которых ответ не засчитают.

## Чего НЕ делать

- ❌ Не сокращай объяснения — переноси их из PDF близко к оригиналу.
- ❌ Не добавляй ничего, чего нет в PDF (никаких "уточнений", "примеров от себя").
- ❌ Не путай ε (эпсилон) и ν (ню) — в PDF они оба встречаются.
- ❌ Не теряй индексы (v₀, R₁, R₂, m₁, m₂ и т.д.). Используй Unicode-подстрочные.
- ❌ Не используй LaTeX — только обычный текст и Unicode символы (²·sin α, √, ≤, ≈, ρ, ω, π, Δ, μ, σ).
- ❌ Не создавай отдельный файл для каждого билета — всё в одном `billets.json`.

## Если что-то сломается

- Если PyMuPDF не установлен — `pip install pymupdf`.
- Если не получается извлечь картинки автоматически — складывай их в `public/images/raw/` с осмысленными именами и в финальном отчёте укажи, что я разложу руками.
- Если какой-то билет в PDF имеет нестандартную структуру (отсутствует "Дано" или "Решение") — отметь это в логе и в `solution_steps` поставь `["см. PDF, нестандартная структура"]`.
